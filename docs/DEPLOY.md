# Выкладка First Year на публичный адрес

Для человека, который ни разу ничего не выкладывал. Займёт 10–15 минут. Нужен только аккаунт GitHub с доступом
к этому репозиторию.

Что выкладываем: один сервис Node на одном порту. Он отдаёт и игру (собранный клиент), и API под `/api`.
Город живёт в памяти и раз в секунду сохраняется на диск (`/data`), поэтому сервису нужен **постоянный том**
(volume) — иначе при каждой выкладке город начинается заново и все игроки теряют свои кофейни.

Образ собирается из `Dockerfile` в корне: Railway сам находит его и собирает по нему.

**Про `railway.json`.** Railway объявил файлы настроек в репозитории (Config as Code) устаревшими: сервисы,
созданные после 28 августа 2026, их не читают, а 1 декабря 2026 их перестанут читать совсем
([Railway: Config as Code](https://docs.railway.com/config-as-code/reference)). Поэтому всё, что важно,
задаётся в панели руками — шаг 2 ниже. `railway.json` остаётся в репозитории как запись тех же настроек для
старых сервисов.

---

## 1. Railway — основной вариант

Почему Railway: сервис работает всё время (у города свои часы, он не должен засыпать), есть постоянные тома,
выкладка идёт прямо из GitHub при каждом пуше. Пробный период даёт разовый кредит $5 на 30 дней — для
хакатона хватает ([Railway: free trial](https://docs.railway.com/pricing/free-trial)).

### Шаг 1. Создать проект из репозитория

1. Откройте https://railway.com и войдите через GitHub (**Login → GitHub**).
2. **New Project** → **Deploy from GitHub repo**.
3. Если Railway просит доступ к репозиториям — **Configure GitHub App**, дайте доступ к репозиторию
   `OHHHeaven`, вернитесь.
4. Выберите репозиторий `OHHHeaven`. Railway создаст сервис и сразу начнёт сборку — пусть идёт.
5. Откройте сервис (карточка на холсте) → **Settings** → **Source** → **Branch**: выберите ветку, которую
   показываем жюри (обычно `main`). Railway будет выкладывать каждый новый пуш в эту ветку.

Сборка занимает 2–4 минуты. Ход виден во вкладке **Deployments** → **View logs**.

### Шаг 2. Настройки сервиса (обязательно)

Сервис → **Settings**. Пройдите сверху вниз:

| Раздел | Поле | Значение | Зачем |
|---|---|---|---|
| **Source** | **Branch** | `main` (или ветка для показа) | что выкладывать |
| **Source** | **Wait for CI** | включить | Railway выкладывает пуш только после зелёного CI — красная сборка не попадёт к жюри |
| **Build** | **Builder** | **Dockerfile** (`Dockerfile` в корне) | обычно выбран сам |
| **Deploy** | **Healthcheck Path** | `/api/health` | новая версия получает посетителей только когда ответила |
| **Deploy** | **Healthcheck Timeout** | `60` | первый запуск поднимает два города |
| **Deploy** | **Restart Policy** | **On Failure**, 10 попыток | сервис встаёт сам после падения |
| **Deploy** | **Serverless** (App Sleeping) | **выключено** | у города свои часы: заснувший сервис останавливает город |
| **Deploy** | **Replicas** | `1` | город живёт в памяти одного процесса: две копии — два разных города |

Если поле называется чуть иначе — ищите по смыслу: интерфейс Railway меняется часто.

### Шаг 3. Подключить том для города

Без этого шага игра работает, но после каждой выкладки город начинается с нуля, а игроки теряют свои кофейни —
и причину вернуться завтра.

1. На холсте проекта нажмите правой кнопкой по пустому месту (или **⌘K / Ctrl+K**) → **New Volume**
   (**Create Volume**).
2. Выберите сервис игры.
3. **Mount path**: `/data` — ровно так, с косой чертой.
4. Railway перевыложит сервис сам.

Образ уже настроен писать снимки в `/data` (`SNAPSHOT_DIR=/data` в `Dockerfile`). Сервис запускается от
`root`, поэтому `RAILWAY_RUN_UID` задавать не нужно.

### Шаг 4. Переменные

Сервис → вкладка **Variables** → **New Variable** (или **RAW Editor**, чтобы вставить всё сразу).
**Игра работает вообще без переменных.** Задавайте только то, что нужно.

| Переменная | Что делает | Нужна? |
|---|---|---|
| `GEMINI_API_KEY` | ключ Google Gemini (Google AI Studio → Get API key). Включает тексты ИИ: события города, советника, разбор сезона | нет: без ключа тексты идут по правилам, игра та же |
| `XAI_API_KEY` | ключ xAI Grok (console.x.ai). Второй провайдер, если первый не ответил | нет |
| `AI_PROVIDER` | порядок провайдеров: `gemini`, `grok`, `grok,gemini` или `mock` (без сети) | нет: по умолчанию Gemini, потом Grok |
| `AI_MODEL` | модель, например `gemini-3.5-flash` | нет |
| `CLOCK_KEY` | пароль на паузу и ускорение демо-городов (`POST /api/worlds/:id/clock`, заголовок `x-clock-key`). Без него любой посетитель может поставить общий демо-город на паузу. С ним кнопки скорости на экране города у посетителей перестают работать, а скрипты показа получают ключ так: `--clock-key <ключ>` | по желанию: на открытом адресе лучше задать, если показ не управляет часами из браузера |
| `DEMO_RESTART_MIN` | через сколько минут после конца сезона демо-город начинается заново | нет: 10 |
| `DATA_DIR`, `SNAPSHOT_DIR` | куда сохранять город | нет: уже `/data` в образе. Меняйте, только если смонтировали том в другое место |
| `PORT` | порт | нет: Railway задаёт сам, сервер его читает |
| `RAILWAY_DEPLOYMENT_DRAINING_SECONDS` | сколько секунд Railway ждёт между «остановись» и принудительной остановкой старой версии. Сервер сохраняет все города по сигналу остановки | желательно `10`. Без неё теряется не больше последней секунды игры: снимок пишется раз в секунду |

Ключи ИИ живут только в переменных сервиса. Не вставляйте их в код, в пакеты и в чаты. Названия переменных
ИИ — по журналу A4 (`ai/README.md` в ветке с Gemini и Grok); пока эта ветка не влита, сервер читает только
`ANTHROPIC_API_KEY`, а без ключа работает на правилах.

После изменения переменных Railway показывает **Deploy** (или **Apply changes**) — нажмите.

### Шаг 5. Публичный адрес

1. Сервис → **Settings** → **Networking** → **Public Networking** → **Generate Domain**.
2. Если Railway спросит порт — `8787` (или оставьте то, что он нашёл сам: сервер слушает `PORT`).
3. Появится адрес вида `https://ohhheaven-production-xxxx.up.railway.app`. Это и есть адрес для жюри.

### Шаг 6. Проверить

1. Откройте адрес в браузере — должна открыться игра.
2. Откройте `<адрес>/api/health` — должно быть `{"ok":true,...}` и два мира: `nyc` и `demo`.
3. Сквозная проверка с любого компьютера с Node 20+ (из папки репозитория):

   ```bash
   node scripts/prod-check.mjs https://ohhheaven-production-xxxx.up.railway.app
   ```

   Скрипт заходит в демо-город как ещё один владелец, открывает кофейню, ждёт месяц торговли и печатает
   выручку. Часы демо-города он не трогает — это 2–4 минуты реального времени. Внизу должно быть
   `prod check: GREEN`. Быстрый вариант за секунду: добавьте `--quick` (здоровье, страница, город, вход).

4. Проверка тома: Railway → сервис → **Deployments** → у последней выкладки **⋮ → Redeploy**. Через минуту
   откройте `/api/health`: день демо-города должен продолжиться, а не начаться с 1. В логах выкладки есть
   строки `restored from snapshot at day …`.

### Если что-то не так

| Что видно | Что делать |
|---|---|
| Новые пуши не выкладываются | включён **Wait for CI**, а CI красный: GitHub → **Actions**. Это защита, а не поломка |
| Сборка красная | **Deployments → View logs**, найдите первую строку `error`. Чаще всего — красная основная ветка: на своём компьютере `npm ci && npm run build` должен проходить |
| Выкладка висит на **Healthcheck** и падает | сервер не поднялся за 60 секунд или в **Healthcheck Path** опечатка. **View logs** → **Deploy logs**. Должна быть строка `First Year server on http://localhost:…` |
| Адрес отвечает 502 | в **Settings → Networking** порт домена не совпадает с тем, что слушает сервер. Поставьте порт из строки `First Year server on …` в логах |
| После выкладки город начался с дня 1 | нет тома или он смонтирован не в `/data` (шаг 3) |
| Игроки видят `Too many requests` | лимит 8 запросов в секунду на посетителя. Задача ведущему — в `agents/r3-B05.md` (`trust proxy`) |

Во время выкладки сервиса с томом Railway сначала останавливает старый контейнер, потом поднимает новый —
игра недоступна 20–40 секунд. Перед показом не пушьте в выкладываемую ветку.

## 2. Запасной вариант — Render

Если Railway недоступен. Минусы: на бесплатном плане сервис засыпает через 15 минут без посетителей
(просыпается около минуты) и не может иметь постоянный диск — город теряется при каждом перезапуске
([Render: deploy for free](https://render.com/docs/free)). На платном плане (Starter) есть диск.

1. https://render.com → войти через GitHub → **New +** → **Web Service**.
2. **Build and deploy from a Git repository** → выбрать `OHHHeaven` → **Connect**.
3. **Language / Runtime**: **Docker**. **Branch**: та, что показываем. **Instance Type**: Free или Starter.
4. **Advanced** → **Health Check Path**: `/api/health`.
5. Только для платного плана: **Advanced** → **Add Disk** → **Mount Path** `/data`, размер 1 GB.
6. Переменные — те же, что в таблице выше (**Environment** → **Add Environment Variable**). `PORT` Render задаёт сам.
7. **Create Web Service**. Адрес — вида `https://ohhheaven.onrender.com`. Проверка — та же:
   `node scripts/prod-check.mjs https://ohhheaven.onrender.com`.

На бесплатном плане за 2 минуты до показа откройте адрес, чтобы сервис проснулся.

## 3. Любой сервер с Docker

```bash
docker build -t first-year .
docker run -d --name first-year --restart unless-stopped -p 80:8787 -v first-year-data:/data first-year
node scripts/prod-check.mjs http://<адрес-сервера> --quick
```

Обновить: `git pull && docker build -t first-year . && docker rm -f first-year` и снова `docker run …` —
город сохранится в томе `first-year-data`.

## 4. Что проверяет CI

`.github/workflows/ci.yml` запускается на каждый пуш в любую ветку:

| Задача | Что делает |
|---|---|
| `check (tsc)` | `npm run check` — типы во всех пакетах |
| `test (vitest)` | `npm test` |
| `smoke (server end to end)` | `node scripts/smoke.mjs` — два владельца, месяц, жалоба, сделка |
| `docker image boots and keeps the world` | собирает образ из `Dockerfile`, поднимает его с томом, `prod-check --new-city` (город, вход, открытие, месяц торговли), потом удаляет контейнер и поднимает новый на том же томе — `prod-check --recall`: мир, владелец и кафе вернулись |

Значок CI — в начале `README.md`. Если Actions выключены в репозитории: **Settings → Actions → General →
Allow all actions**.

**Проверка публичного адреса снаружи** — `.github/workflows/prod-check.yml`. Один раз задайте адрес:
GitHub → репозиторий → **Settings → Secrets and variables → Actions → Variables → New repository variable**:
имя `PROD_URL`, значение `https://<адрес>.up.railway.app`. Если на сервере задан `CLOCK_KEY` — там же во вкладке
**Secrets** секрет `CLOCK_KEY`. Дальше каждые 30 минут GitHub делает быструю проверку (здоровье, страница, город,
вход), а кнопка **Actions → Prod check → Run workflow** запускает полную: открытие кофейни и месяц торговли.
Плановые проверки идут только из основной ветки.
