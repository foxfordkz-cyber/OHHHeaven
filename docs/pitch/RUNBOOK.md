# Показ жюри: что запустить и что нажать

Сценарий сцены — `docs/pitch/LIVE-SHOW.md`. Этот файл — техника: как поднять город показа, проверить его, вернуть в начало и что нажимать по ходу пяти минут. Всё ниже проверено на ветке `claude/kind-galileo-oanrkd` 14 ноября 2026 (UTC); числа в примерах — из прогона того дня и изменятся вместе с движком. Читать со сцены только числа с экрана.

## Что делает город показа

`POST /api/worlds { "scenario": "pitch" }` собирает город `pitch` **обычными действиями игры и игровыми днями**, без правки итогов:

1. Город с восемью кафе под управлением ИИ — Alba, Noor, June, Luca, Hana, Eli, Rosa, Theo (у каждого `isAi`, метка AI в интерфейсе) — и двумя ИИ-чиновниками: **Sam** (налоговый инспектор) и **Dana** (санитарный инспектор). Характеры жителей — без жалоб и без срезанных углов, чтобы Sam был свободен, когда придёт жалоба Maya.
2. Входят два человека-владельца: **Maya** и **Viktor**. Они открывают **Maya's Coffee** и **Viktor's Coffee** на двух свободных соседних дверях (меньше 250 м — общий пешеходный поток) по совету открытия игры: Maya — самый маленький набор, у неё есть место добавить шесть стульев.
3. Обе ждут ремонта и всех разрешений и открывают двери без нарушения. На новом движке это месяцы игры (31–111 дней в зависимости от помещения), поэтому подготовленный момент — около 120-го дня (конец апреля).
4. За 30 игровых дней до подготовленного момента Viktor включает срезанный угол из общего пакета — **«Pay staff in cash, off the books»** (`cash_wages`, нарушение `off_books_payroll`). Это и есть «накопленная история нарушения».
5. Maya и Viktor «смотрят на телефоны» в этот день (как при обычном открытии экрана), поэтому на сцене телефон открывает кофейню, а не окно «While you were away».
6. Город встаёт на паузу. Это **стартовая копия**: команда `reset` возвращает в неё одной командой, токены телефонов остаются.

Затем сборка на копиях города проверяет, что сцена пройдёт: обе ветки жюри принимаются движком, жалоба Maya даёт **новое** дело именно по зарплате и уведомление о штрафе, у Viktor хватает денег заплатить. Если пара дверей не годится (кто-то разорился, не дождавшись дверей), сборка берёт следующую пару и пишет это в журнал сборки.

Сборка идёт около 20–25 секунд расчёта. Делается один раз до выхода; дальше город лежит в снимке и поднимается при перезапуске сервера с теми же кодами.

## Подготовка: за час до выхода

Все команды — из корня репозитория на ноутбуке показа.

1. Зафиксировать версию: последний зелёный коммит, больше ничего не вливать.

```bash
git log --oneline -1
```

2. Зависимости и сборка клиента (сервер раздаёт `client/dist` телефонам).

```bash
npm install
```

```bash
npm run build
```

3. Прогон показа: собирает свой город на свободном порту, проходит обе ветки жюри по HTTP и меряет каждый шаг против окна сценария. Должно закончиться строкой `PASS: 16/16 steps in their windows`.

```bash
node scripts/pitch.mjs
```

4. Сервер показа. `HOST=0.0.0.0` — чтобы телефоны в той же сети достучались; `PITCH=1` — собрать город при старте (или поднять из снимка); `CLOCK_KEY` — чтобы паузу и команды не нажал кто-то из зала по гостевой ссылке.

```bash
HOST=0.0.0.0 PORT=8787 PITCH=1 CLOCK_KEY=stage-key npm start
```

Если ноутбук видит несколько сетей и выбирает не ту, адрес для QR задаётся явно:

```bash
HOST=0.0.0.0 PORT=8787 PITCH=1 CLOCK_KEY=stage-key PUBLIC_URL=http://192.168.1.5:8787 npm start
```

5. Ссылки и коды для этого запуска (адрес — сеть ноутбука, не `localhost`):

```bash
PITCH_URL=http://127.0.0.1:8787 CLOCK_KEY=stage-key node scripts/pitch-ctl.mjs codes
```

Выводит гостевой код (четыре буквы, ссылка на QR), коды Maya и Viktor (шесть букв) и адрес пульта ведущего `/pitch`. Коды владельцев видны только с ключом часов.

6. Тот же прогон на живом сервере показа — проверка сети и кодов на настоящем оборудовании:

```bash
PITCH_URL=http://127.0.0.1:8787 CLOCK_KEY=stage-key node scripts/pitch.mjs
```

Он сам возвращает город в начало в конце. После него — ещё раз `reset` (ниже) перед выходом.

### Телефоны и проектор

| Устройство | Что открыть | Что увидит |
|---|---|---|
| Телефон А (Maya) | `http://<адрес>/p/<код Maya>` | Страница кладёт сессию Maya в браузер и открывает `/biz` — её кофейня |
| Телефон Б (Viktor) | `http://<адрес>/p/<код Viktor>` | То же для Viktor |
| Проектор | `http://<адрес>/p/<гостевой код>` в отдельном профиле браузера | Город без владельца: карта, лента, соседи |
| Жюри | QR `http://<адрес>/p/<гостевой код>/qr.svg` на экране или на листе | Гостевой вид города на своём телефоне |

Код можно набрать руками: `http://<адрес>/p` — поле для кода. Буквы без похожих (нет I, O, 0, 1), регистр не важен. Частные экраны — в разных профилях браузера: сессии лежат в `localStorage` по городу, одна вкладка с Maya и одна с Viktor в одном профиле перепишут друг друга.

## Пульт ведущего и команды

**Пульт в браузере** — `http://<адрес>/pitch` на ноутбуке Б (не на проекторе). Большие кнопки: Pause, Resume · 1 s/day, +1 day, +7 days, Back to start, две ветки жюри, «Maya reports Viktor · run to notice». Рядом — состояние Maya, Viktor и дела, гостевой QR, коды телефонов и проверки города. Ключ часов вводится один раз за сеанс браузера. Консоль на сцене не нужна.

**Те же команды из терминала** (одна команда — одно действие; сервер — `PITCH_URL`, ключ — `CLOCK_KEY`):

```bash
export PITCH_URL=http://127.0.0.1:8787 CLOCK_KEY=stage-key
```

| Что | Команда |
|---|---|
| Вернуть город в исходное состояние | `node scripts/pitch-ctl.mjs reset` |
| Пауза | `node scripts/pitch-ctl.mjs pause` |
| Снять паузу (день за секунду) | `node scripts/pitch-ctl.mjs resume 1000` |
| Перемотать на N игровых дней (до 60) | `node scripts/pitch-ctl.mjs advance 7` |
| Скорость без снятия паузы | `node scripts/pitch-ctl.mjs speed 2000` |
| Ветка жюри «выше цены» за Maya | `node scripts/pitch-ctl.mjs branch price` |
| Ветка жюри «больше мест» за Maya | `node scripts/pitch-ctl.mjs branch seats` |
| Жалоба Maya на Viktor; город идёт до уведомления и сам встаёт на паузу | `node scripts/pitch-ctl.mjs complaint` |
| Состояние / коды | `node scripts/pitch-ctl.mjs status` / `codes` |
| Собрать город / собрать заново с новыми кодами | `node scripts/pitch-ctl.mjs build` / `rebuild` |

Под капотом — `POST /api/worlds/pitch/pitch {"command": ...}` с заголовком `x-clock-key`.

Ветки и жалоба с пульта — запасной путь, если телефон не отвечает: те же обычные действия игры, что А делает на телефоне. Основной путь — руками на телефоне.

## По ходу пяти минут

Время — сценическое, по партитуре LIVE-SHOW.

| Время | Кто | Что нажать | Что проверить глазами |
|---|---|---|---|
| до выхода | Б | Пульт: Back to start; телефоны и проектор открыты, город на паузе | На проекторе дата подготовленного момента и режим Demo; телефон Maya открывается сразу на Today, без окна «While you were away» |
| 1:20–1:40 | А | Телефон Maya: вкладка Today, затем Manage | На Today заметка «Packed: …% of seats in use» (проверка `room_full`). Потерянных гостей сегодня 0 — см. реплику ниже |
| 1:40–2:00 | А | Manage: цена +10% **или** зал +6 мест; прогноз; сохранить | Прогноз месяца обновился; «This is a model, not a promise» |
| 2:00–2:40 | А / Б | Ничего не трогать в городе; Б показывает срезанный угол Viktor в Manage | У Viktor включено «Pay staff in cash, off the books» |
| 2:40 | А | Телефон Maya: Network → Viktor's Coffee → Report → «Report unpaid taxes or off-the-books wages» | Во входящих Maya: «Report filed» |
| 2:40–3:00 | Б | Пульт: Resume · 1 s/day; после уведомления — Pause | Дело Sam (AI): уведомление о штрафе по `off_books_payroll`. Сегодня это 1 игровой день ≈ 1 секунда |
| 3:00–3:20 | Б | Телефон Viktor: уведомление → Pay | Касса Viktor уменьшилась на штраф с экрана |
| после | Б | Пульт: Back to start | День подготовленного момента, пауза, жалобы нет |

Если А на сцене не успевает отправить жалобу с телефона, Б нажимает на пульте «Maya reports Viktor · run to notice»: жалоба, ход времени и автопауза на уведомлении.

## Проверки города и как читать WARN

`checks` в состоянии показа — то, что сборка проверила на копии города:

| Проверка | Уровень | Если не прошла |
|---|---|---|
| `open`, `permits` | must | Пересобрать: `node scripts/pitch-ctl.mjs rebuild` |
| `neighbors` | must | Пересобрать; если повторяется — в данных мест нет двух свободных соседних дверей |
| `branch_price`, `branch_seats` | must | Ветку на сцене не предлагать; реплика LIVE-SHOW: “Let’s try the price first.” |
| `violation`, `can_pay` | must | Пересобрать |
| `complaint` | must | Не обещать живую проверку: «Here is the audit from our earlier completed run.» |
| `room_full` | should | Зал Maya в среднем занят на 80% и больше за неделю — вопрос «больше мест?» честный. Сегодня PASS (85%). Если WARN — не предлагать ветку мест: “Let’s try the price first.” |
| `customers_lost` | should | **Сегодня WARN:** на текущем движке Maya не теряет гостей ни из-за мест, ни из-за штата. Реплику “Customers arrive, but some leave without buying.” не говорить. Вместо неё — то, что видно на Today: “Her room is packed. Raise the price, or add seats?” |

Сценарий не зависит от точных сумм: проверки — условия, а суммы на сцене — то, что посчитал движок в момент показа. Если движок поменялся, `node scripts/pitch.mjs` покажет новые числа и новый итог проверок.

## Город показа на публичном адресе

Выкладка — задание B05 (`docs/DEPLOY.md`). Для города показа на публичном сервере:

- **Обязательно задать `CLOCK_KEY`.** На сервере с `NODE_ENV=production` без ключа команды показа отклоняются («Set CLOCK_KEY on the server to control the pitch city»), а коды владельцев не показываются: иначе любой из зала мог бы сбросить город или войти за Maya.
- `PITCH=1` собирает город уже после старта сервера (проверка здоровья не ждёт 20–25 секунд расчёта); снимок поднимается при перезапуске.
- QR и ссылки входа берут адрес, по которому открыт пульт (`X-Forwarded-Host`, `X-Forwarded-Proto` за прокси Railway) — публичный домен с `https`. С `localhost` — адрес ноутбука в сети. `PUBLIC_URL` перекрывает и то и другое.
- Сервер пишет снимки в `SNAPSHOT_DIR` (по умолчанию `server/.snapshots`). На Railway без постоянного тома город показа после перезапуска собирается заново с новыми кодами — перепечатать QR.

Проверка на публичном адресе (собрать, если ещё нет, и прогнать обе ветки):

```bash
PITCH_URL=https://<публичный адрес> CLOCK_KEY=<ключ> node scripts/pitch-ctl.mjs build
```

```bash
PITCH_URL=https://<публичный адрес> CLOCK_KEY=<ключ> node scripts/pitch.mjs
```

## Если что-то пошло не так

| Сбой | Действие |
|---|---|
| Город убежал вперёд | Пульт: Back to start (или `node scripts/pitch-ctl.mjs reset`) — та же стартовая копия, телефоны остаются в своих кофейнях |
| Сервер перезапустился | Город показа поднимается из снимка `server/.snapshots/pitch.json` и `pitch.setup.json` с теми же кодами |
| Телефон показывает чужую кофейню или «Join» | Ещё раз открыть `/p/<код владельца>`; гостевой код сессию владельца стирает |
| QR не открывается с телефона | Проверить, что телефон в той же сети; адрес в QR — `join.base` из состояния показа; при нескольких сетях задать `PUBLIC_URL` |
| Нужен совсем новый город (новые коды) | `node scripts/pitch-ctl.mjs rebuild` — 20–25 секунд, коды меняются: перепечатать QR |

## Что это не делает

- Не рисует итоги: штраф, прибыль и касса — расчёт движка. Если на экране другие деньги, переписываем подсказку выступающего.
- Не гарантирует, что QR работает после выключения ноутбука: город живёт на ноутбуке показа. Для печатного листа — только после проверки постоянного размещения.
- Отдельная запись экрана и завершённый прогон для личного плана — подготовка исполнителей (LIVE-SHOW, раздел 5), не этот сервер.
