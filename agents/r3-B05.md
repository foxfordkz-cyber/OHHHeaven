## Как проверить одной командой

```bash
docker build -t first-year . && docker run -d --name fy -p 8787:8787 -v fy-data:/data first-year && node scripts/prod-check.mjs http://127.0.0.1:8787 --wait 60 --new-city
```

Против выложенного адреса (заходит в общий `demo`, его часы не трогает, ~2–3 минуты реального времени):

```bash
node scripts/prod-check.mjs https://<адрес>.up.railway.app
```

## Что сделано

| Файл | Что |
|---|---|
| `Dockerfile` | Сначала манифесты и `npm ci` (слой кешируется), потом код, сборка клиента, `npm prune --omit=dev`. **Исправлена потеря мира при выкладке:** сервер читает `SNAPSHOT_DIR`, а образ задавал только `DATA_DIR` — снимки писались в `/app/server/.snapshots` внутри контейнера и пропадали при каждой новой выкладке. Теперь `SNAPSHOT_DIR=/data` и `DATA_DIR=/data`. Сервер запускается `node …/tsx/dist/cli.mjs server/src/main.ts` напрямую, без `npm start`: `SIGTERM` доходит до сервера и он сохраняет все миры перед выходом. |
| `.dockerignore` | Не везёт в образ `research_notes`, `reports`, `agents`, `.github`, `server/.snapshots` (файл не в списке задания, но им никто не владеет и он про выкладку). |
| `scripts/prod-check.mjs` | Сквозной прогон против адреса: здоровье → страница и её файлы, глубокая ссылка → город → вход владельца → открытие кофейни (стройка, отказ в раннем запуске, запуск) → первый месяц торговли с выручкой > 0 → аналитика. `--quick`, `--new-city`, `--remember`/`--recall` (мир, владелец и кафе после перезапуска), `--clock-key`, `--wait`. |
| `.github/workflows/ci.yml` | На каждый пуш: `check`, `test`, `smoke` отдельными задачами; задача `docker`: собрать образ, поднять с томом, `prod-check --new-city`, удалить контейнер, поднять новый на том же томе, `prod-check --recall`. |

## Что мешает выкладке — просьбы к ведущему (серверный код не мой)

1. **`app.set('trust proxy', 1)` в `server/src/index.ts` (`createApp`).** За прокси Railway `req.ip` у всех гостей без токена один и тот же — адрес прокси. Лимит 8 запросов в секунду (запас 40) делится на всех гостей сразу. Гость города опрашивает `/view` раз в 2 секунды в демо → больше ~16 одновременных гостей без входа начнут получать 429, а на показе с QR-кодом это реально. Одна строка; на тестах не скажется.
2. **Каждый `POST /api/worlds` навсегда занимает один из 20 слотов демо-городов**: закончившийся сезон перезапускается, снимок поднимается после перезапуска. Клиент города не создаёт, поэтому для игроков не опасно, но `SMOKE_URL=<прод> node scripts/smoke.mjs` и `prod-check --new-city` против прода съедают слоты. Поэтому `prod-check` по умолчанию заходит в общий `demo`. Если нужно — `DELETE` для демо-городов или не перезапускать созданные города.
3. `scripts/smoke.mjs` передаёт серверу `DATA_DIR`, а сервер читает `SNAPSHOT_DIR` — снимки сквозного прогона пишутся в `server/.snapshots` (не мешает, просто мусор в рабочей папке).
