## Как проверить одной командой

```bash
node scripts/e2e/journey.mjs
```

Сам поднимает сервер на свободном порту со своим временным каталогом снимков (собирает клиент, если нет `client/dist`), проходит путь игрока в Chromium на 375 и 1440 и пишет `docs/qa/runs/<время>/RUN.md`, `results.json` и снимки каждого экрана (папка `runs/` в git не идёт). Код возврата 1, если хоть один шаг через интерфейс не прошёл.

- **Всё против выложенной игры одной командой:** `scripts/e2e/prod.sh https://<адрес> [CLOCK_KEY]` — путь игрока на 375 и 1440, первая минута, скорость первого экрана и (с ключом) живой показ; ждёт сервер до 2 минут. С `CLOCK_KEY` на сервере часы любого города слушаются только ключа — без него путь не пройдёт.
- Только путь против выложенной игры: `node scripts/e2e/journey.mjs --url https://<адрес> --key <CLOCK_KEY>` (без конца сезона; с концом — `--end`; свой город остаётся на паузе, см. `BUGS.md`, №15).
- Против любой ветки в отдельной рабочей копии рядом с репозиторием: `scripts/e2e/cycle.sh <ветка>` (по умолчанию ветка сборщика B04).
- Снимки для презентации (вид экрана; телефон ×2): `--shots <папка>`. Тёмная тема: `--scheme dark`. Без конца сезона: `--no-end`.
- Первая минута новичка на демо-скорости, в секундах: `node scripts/e2e/first-minute.mjs`.
- Скорость первого экрана (компьютер и телефон на Slow 4G): `node scripts/e2e/perf.mjs`.
- Живой показ в четырёх браузерах (телефоны Maya и Viktor, проектор, пульт): `node scripts/e2e/pitch-show.mjs` (`--branch seats` — вторая ветка жюри).

## Что проверяет прогон

Гость → главная, поле идеи → «See my plan» → идея распознана → место по карману, «Open here» → план открытия → вход с именем → 14 карточек решений (собственный выбор на первой карточке с вариантами двигает «cash left / bills a month»; «Next» на экране?) → «Sign the lease» → ждём разрешения → «Open doors» → экран бизнеса, «While you were away» → шесть вкладок (Today без советов с минусом) → Manage: +$0,50 к цене, прогноз до сохранения, «Apply», на следующий день «Your change» на Today → «Apply» у совета → правка цены при идущих часах → сосед (через API, с тестовым Pro) → сделка из листа соседа → ответ на входящее предложение → жалоба → стол инспектора в своём браузере → `/brief` через 3 недели → месяц → после бесплатного месяца: план бесплатного игрока, отказ «Apply», кнопка Pro, `/pro` → «Get Pro» → изменение проходит → конец сезона → личный план.

На каждом шаге: снимок экрана, горизонтальная прокрутка, ошибки страницы и консоли, неудачные запросы, ответы API 5xx.

## Решения

- Каждый прогон создаёт свой демо-город (`POST /api/worlds`) и ставит его часы на паузу: прогон не зависит от общего демо-города, дни двигаем сами (`/clock advanceDays`).
- Прогон не останавливается на первой поломке: шаг, который не прошёл через интерфейс, делается через API, чтобы проверить экраны дальше. В отчёте такой шаг — FAIL с пометкой «(API)».
- Соседа открываем через API (барбершоп рядом; после B14 ему нужен тестовый Pro). Сделку, ответ на предложение и жалобу игрок делает в браузере.
- Снимок шага — когда экран готов, до клика, который уводит; пауза 0,7 с (экраны появляются с анимацией).
- Снимки компьютера — ×1: полноэкранный снимок ×2 на 1440 растягивает карту WebGL, и headless Chromium перестаёт рисовать страницу. Особенность проверки, не игры.
- Против выложенной игры прогон не доводит сезон до конца и оставляет свой город на паузе (№15).
- «Основная ветка» для круга — ветка сборщика B04: из неё перематывается основная.
- Числа в поломках не правлю и не подгоняю: в `BUGS.md` — то, что показал прогон; где прогон сам что-то меняет (цена +$0,50, совет), так и написано.
- Исправленные поломки не удаляю: они в разделе «Исправлено» с коммитом и тем, как проверено.
