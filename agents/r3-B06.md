## Как проверить одной командой

```bash
node scripts/e2e/journey.mjs
```

Сам поднимает сервер на свободном порту со своим временным каталогом снимков (собирает клиент, если нет `client/dist`), проходит путь игрока в Chromium на 375 и 1440 и пишет `docs/qa/runs/<время>/RUN.md`, `results.json` и снимки каждого экрана (папка `runs/` в git не идёт). Код возврата 1, если хоть один шаг через интерфейс не прошёл.

- Против выложенной игры: `node scripts/e2e/journey.mjs --url https://<адрес>`.
- Против ветки сборщика B04 в отдельной рабочей копии рядом с репозиторием: `scripts/e2e/cycle.sh` (по умолчанию `origin/claude/cool-archimedes-blis6z`; другую ветку — первым аргументом).
- Снимки для презентации (вид экрана, ×2): `--shots docs/qa/screens`.
- Без прогона до конца сезона (быстрее на минуту): `--no-end`.

Гость → главная, поле идеи → «See my plan» → идея распознана → место по карману, «Open here» → план открытия (шаги, ссылки на официальные страницы) → вход с именем → набор, «Open with recommended setup» → ждём разрешения (дни идут по 5) → «Open doors» → экран бизнеса, «While you were away» → вкладки Today, Manage, Books, Network, Insights → Manage: +$0,50 к цене, прогноз меняется до сохранения, «Save settings», цена дошла до движка, следующий день → сосед открывается рядом (через API) → сделка cross-promo из листа соседа, сосед принимает → жалоба из «Report to the city», дело у инспектора → месяц, отчёт в Books → конец сезона, «Open my plan» → личный план.

## Решения

- Каждый прогон создаёт свой демо-город (`POST /api/worlds`) и ставит его часы на паузу: прогон не зависит от того, что уже открыто в общем демо-городе, а дни двигаем сами (`/clock advanceDays`).
- Прогон не останавливается на первой поломке: шаг, который не прошёл через интерфейс, делается через API, чтобы проверить экраны дальше по пути. В отчёте такой шаг — FAIL с пометкой «(API)».
- Соседа для сделки и жалобы открываем через API (барбершоп рядом: cross-promo разрешён только между разными видами бизнеса). Сделку и жалобу игрок делает в браузере.
- Снимок каждого шага делается, когда экран готов, до клика, который уводит с него; пауза 0,7 с перед снимком — экраны появляются с анимацией, мгновенный снимок пустой.
- «Основная ветка» для круга — ветка сборщика B04: из неё третий ведущий перематывает основную. Сама основная (`claude/global-entrepreneur-product-133cix`) проверяется тем же `cycle.sh <ветка>`.
- Числа в поломках не правлю и не подгоняю: в `BUGS.md` — то, что показал прогон.
