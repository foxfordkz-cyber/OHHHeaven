## Что сделано

- **Провайдер Gemini** — `ai/src/provider/gemini.ts`. REST `generateContent`, структурированный ответ через `responseJsonSchema`, ключ в заголовке `x-goog-api-key`, «размышление» на минимуме для скорости.
- **Провайдер Grok** — `ai/src/provider/grok.ts`. REST xAI Responses API (`/v1/responses`), `text.format` с `json_schema` и `strict: true`, ключ в `Authorization: Bearer`, `store: false`.
- **Общий HTTP** — `ai/src/provider/http.ts`: один POST, ошибки в `AiFailure`, схема zod → JSON Schema, разбор ответа той же схемой zod, что и раньше.
- **Цепочка** — `ai/src/provider/index.ts`: основной провайдер → второй → запасной путь без ИИ. Восемь секунд на всю цепочку. Кэш, лимит в минуту и журнал вызовов остались. В журнале каждая попытка отдельной строкой, ключей там нет.
- **Anthropic выключен.** Адаптер оставлен, но в цепочку попадает, только если его явно назвать в `AI_PROVIDER`.
- События города, советник, подбор ниши и разбор сезона идут через `callAi`, поэтому сразу работают через новую цепочку. Без ключей ответ дают правила, как раньше.

## Переменные, которые задаёт человек (только на сервере)

| Переменная | Что | По умолчанию |
|---|---|---|
| `GEMINI_API_KEY` | ключ Google Gemini API (Google AI Studio) | нет — Gemini пропускается |
| `XAI_API_KEY` | ключ xAI API (console.x.ai) | нет — Grok пропускается |
| `AI_PROVIDER` | основной провайдер: `gemini`, `grok` или `mock` (без сети). Можно списком: `grok,gemini` | не задан: сначала Gemini, потом Grok |
| `AI_MODEL` | модель. Уходит провайдеру, чьё семейство названо (`gemini-…` → Gemini, `grok-…` → Grok); без узнаваемого начала — основному | `gemini-3.5-flash` / `grok-4.20-non-reasoning` |
| `GEMINI_MODEL`, `XAI_MODEL` | модель каждого провайдера отдельно, когда `AI_MODEL` её не задаёт | как выше |
| `AI_TIMEOUT_MS` | бюджет всей цепочки | 8000, больше нельзя |
| `AI_PRIMARY_MS` | сколько из бюджета ждать основной провайдер, если есть второй | 5000 |
| `AI_MAX_RPM` | вызовов в минуту | 20 |
| `AI_LOG=1` | печатать журнал вызовов в stderr | выключено |
| `GEMINI_THINKING` | уровень «размышления» Gemini (`minimal`, `low`, … или число-бюджет) | по модели, минимальный |
| `GEMINI_BASE_URL`, `XAI_BASE_URL` | другой адрес API (прокси) | официальные адреса |

Достаточно одного ключа: тогда цепочка — этот провайдер → правила. С двумя ключами — основной → второй → правила.

## Решения и почему

- **Документация.** Сайты `ai.google.dev` и `docs.x.ai` из песочницы закрыты (прокси отказывает, у помощника для чтения страниц — не находится адрес). Поэтому сверял по двум источникам:
  1. выдача поиска по страницам документации;
  2. исходники официальных пакетов из npm свежих версий: `@ai-sdk/google` 4.0.121 (12 ноября 2026) и `@ai-sdk/xai` 5.0.46 (13 ноября 2026).

  Из них взяты адреса, заголовки, поля запроса и ответа, причины остановки и текущие названия моделей. По памяти не брал ничего.
- **Grok через Responses API, а не Chat Completions.** В `@ai-sdk/xai` 5.0.0 Chat Completions удалён («remove Chat Completions API»), по умолчанию — `/v1/responses`. Делаю так же, чтобы не завязаться на уходящий путь.
- **Модель Grok по умолчанию — `grok-4.20-non-reasoning`.** Текущая линейка xAI: `grok-4.20-non-reasoning`, `grok-4.20-reasoning`, `grok-4.3`, `grok-latest`, а также `grok-4.5`–`grok-4.7`, которые всегда размышляют. Модель без размышления быстрее отвечает и укладывается в 8 секунд. Поле `reasoning` она отвергает, поэтому не отправляю его.
- **Модель Gemini по умолчанию — `gemini-3.5-flash`.** Это стабильная flash-модель без «preview» в названии, и на ней размышление опускается до `minimal`. Правило уровня взял из каталога `@ai-sdk/google`:
  - Gemini 3+ flash до 3.7 — `minimal`; pro и flash с 3.7 — `low`;
  - Gemini 2.5 — `thinkingBudget: 0` (у 2.5 pro — 128).
- **Схема.**
  - Gemini: `$schema` убираю, `const` → `enum` из одного значения (так делает `@ai-sdk/google`: в `responseJsonSchema` нет `const`).
  - Grok: дополнительно убираю `minLength`, `maxLength`, `pattern`, `minItems`, `maxItems`. Строгий режим xAI их, по сторонним руководствам, не поддерживает.
  - Ответ всё равно проверяет та же схема zod, так что ослабление ничего не пропустит.
- **Бюджет цепочки.**
  - Восемь секунд на всё. Если за основным стоит второй провайдер, основной ждём не дольше 5 секунд (`AI_PRIMARY_MS`), тогда второму остаётся не меньше 3.
  - Быстрый отказ (нет ключа, 429, 500) сразу передаёт ход второму.
  - Ответ, не прошедший проверку правдоподобия (числа не из данных и т. п.), тоже передаёт ход второму, если время осталось.
  - Меньше 300 мс второго не запускаю.
- **Форма «или null».** zod пишет `nullable` у строки как `type: ["string","null"]`, а у массива — как `anyOf`. Привожу всё к `anyOf` с `{type: "null"}`: провайдеру нужно понимать только одну форму. Границы ±2⁵³, которые zod ставит у `int()`, убираю: для модели это шум, а не правило игры.
- **Без SDK.** Оба API — обычный JSON по HTTPS. `fetch` проще, не добавляет зависимостей и легко подменяется в тестах. Зависимость `@anthropic-ai/sdk` оставлена для выключенного адаптера; удалять её — правка корневого `package-lock.json`, это общий файл.
- **Anthropic.** Задание: «API Anthropic в игре не будет», «адаптер можно оставить выключенным». Оставил: в цепочку не попадает, пока `AI_PROVIDER` его не назовёт.
