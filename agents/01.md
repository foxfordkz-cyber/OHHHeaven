## Решения и почему
- **Версии:** TypeScript 5.9.3, vitest 3.2.7, vite 7.3.8, @vitejs/plugin-react 4.7.0, React 19.3.1, Express 5.3.0, tsx 4.23.15, concurrently 9.2.5.
  - Это стабильные и проверенные связки.
  - TypeScript 7 (нативный компилятор) не беру, чтобы не ловить расхождения у агентов.
  - Vite сначала стоял 6.4.6, но vitest притянул 7.3.8 и типы плагина разошлись, поэтому один vite 7.3.8 на весь репозиторий.
- **Пакеты отдают исходники `.ts`** через `exports` (`"." → "./src/index.ts"`); сборки пакетов нет.
  - TypeScript (`moduleResolution: Bundler`), tsx, Vite и vitest читают их напрямую.
  - У engine есть подпуть `@ohh/engine/<модуль>` → `src/<модуль>/index.ts`.
- **Сервер в продакшене запускается через tsx**, без компиляции: один процесс Node, один порт (`PORT`, по умолчанию 8787).
- **`npm test` и `npm run check` идут по каждому пакету** (`--workspaces --if-present`), чтобы у владельцев были свои конфиги vitest. `--passWithNoTests`, чтобы пустой пакет не ронял прогон.
- **Метка заглушки:** первая строка `// @ohh-stub`. По ней smoke понимает, что модуль ещё не настоящий. Владелец, заменяя файл, просто удаляет строку.
- **BotBrain** объявлен в `bots/src/index.ts` (контракт §7 не называет файл), реализация-заглушка — `botBrain`. Хост берёт тип оттуда.
