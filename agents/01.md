## Как проверить

```bash
npm install && npm run check && npm test && node scripts/smoke.mjs
```

Ожидается:
- `check` без ошибок;
- в 7 пакетах `Test Files … passed`;
- smoke печатает 8 строк `✔ … [stub: …]` и `smoke: GREEN — 0 step(s) on real code, 8 on stubs`.

Заглушка исчезает, когда владелец заменяет файл: из скобок пропадает его модуль, а при полном наборе настоящих частей там появляется `REAL`.

## Решения и почему
- **Хостинг — Railway.** Город идёт по своим часам, поэтому нужен постоянный процесс и том под снимки.
  - [Render free](https://render.com/docs/free) засыпает через 15 минут без трафика и не даёт диска.
  - У [Fly.io](https://fly.io/docs/about/discontinued-plans/) для новых организаций нет бесплатного лимита.
  - [Railway](https://docs.railway.com/pricing/free-trial) даёт триал $5 на 30 дней, тома и деплой Dockerfile из GitHub. Этого хватает на хакатон.
- **В Dockerfile `CMD ["npm", "start"]`**, чтобы деплой следовал скрипту `start` владельца сервера (06), даже если тот сменит файл входа. Снимки пишутся раз в секунду, поэтому при остановке теряется не больше секунды.

- **Версии:** TypeScript 5.9.3, vitest 3.2.7, vite 7.3.8, @vitejs/plugin-react 4.7.0, React 19.3.1, Express 5.3.0, tsx 4.23.15, concurrently 9.2.5.
  - Это стабильные связки. TypeScript 7 (нативный) не беру, чтобы не ловить расхождения у агентов.
  - Vite один на весь репозиторий, 7.3.8, потому что его тянет vitest: с 6.4.6 у клиента разошлись типы плагина.
- **Пакеты отдают исходники `.ts`** через `exports` (`"." → "./src/index.ts"`), сборки пакетов нет.
  - Их напрямую читают TypeScript (`moduleResolution: Bundler`), tsx, Vite и vitest.
  - У engine есть подпуть `@ohh/engine/<модуль>` → `src/<модуль>/index.ts`.
- **Продакшен:** сервер запускается через tsx без компиляции — один процесс Node, один порт (`PORT`, по умолчанию 8787).
- **`npm test` и `npm run check` идут по каждому пакету** (`--workspaces --if-present`), чтобы у владельцев были свои конфиги vitest.
- **Метка заглушки — строка `// @ohh-stub`.** Smoke по ней понимает, что модуль ненастоящий.
  - Модули движка (`economy`, `law`, `deals`, `analytics`) считаются настоящими, только если настоящий и сам `engine/src/index.ts`: мини-движок их не вызывает.
  - Шаг на заглушке, который упал, отмечается `–` и не красит прогон. Красный прогон — только при падении шага, в котором всё настоящее.
- **Заглушки — сквозные, а не пустые.** Клиентские агенты 08–12 уже сейчас могут работать с живым сервером на форме данных из контракта, а smoke проверяет весь путь.
  - Все числа в заглушечных данных — `estimate` с пометкой «stub for wiring only».
  - Сервер подменяет их настоящими файлами, как только те появятся.
- **`BotBrain`** объявлен в `bots/src/index.ts`, реализация-заглушка — `botBrain`. Контракт §7 не называет файл. Хост и сервер берут тип и реализацию оттуда.
- **Тело `action` и `query`:** сервер принимает и `{ action }` / `{ query }`, и сам объект с полем `type`. Контракт форму не задаёт, а клиенту так проще.
- **Время в журнале** — по `date -u` контейнера (11:45 — начало работы).
