# 23 — Конвейер «новость → событие»

**Главный принцип.** Цифры берутся из данных, слова — из новостей, а модель только соединяет одно с другим. Модель выбирает шаблон и параметры из закрытых списков. Силу эффекта считает код: по реальному числовому ряду или по фиксированной таблице. Если источник не подтверждён, событие не создаётся.

Цены моделей (Anthropic, ноябрь 2026, за 1 млн токенов вход / выход): Opus 5.5 — $4 / $20, Sonnet 5.5 — $2 / $10, Haiku 5.5 — $0.10 / $0.50. Batch API даёт скидку 50%. Серверный веб-поиск стоит $10 за 1 000 запросов, но он нам не нужен: GDELT бесплатен.

## 1. Шаги конвейера (раз в сутки, cron в 06:00 UTC)

```
сбор → фильтр → значимость → подтверждение → шаблон → проверка → файл мира → матчи
 код     код       модель         код          модель      код        код        код
```

| Шаг | Кто | Что происходит |
|---|---|---|
| 1. Сбор | код | **GDELT DOC 2.0 API** (ключ не нужен): ~40 запросов (10 товаров × 4 набора слов, например `"coffee" harvest OR frost OR drought`), только за последние 24 часа. **Данные:** World Bank Pink Sheet — месячные цены кофе, какао, сахара, пшеницы; FAO Food Price Index (молочка); курсы ЕЦБ (ежедневный XML); Open-Meteo (погода в городах матчей); Nager.Date (праздники). Всё приводится к виду `{id, title, url, domain, seen_at, lang}`, дубли отсекаются по хэшу. Итог — ~500–700 заголовков в сутки (оценка). |
| 2. Фильтр | код | Белый список доменов: агентства (Reuters, AP, AFP), BBC, Guardian, FT, Bloomberg, Nikkei, DW, Al Jazeera, а также официальные сайты (fao.org, worldbank.org, ecb.europa.eu, eia.gov, usda.gov, reliefweb.int). Словарь «слово → товар». Похожие заголовки склеиваются в кластеры (сходство слов ≥ 0,6). Стоп-лист тем (см. §2). Итог — ~40–60 кластеров. |
| 3. Значимость | модель | Один вызов на все кластеры сразу. Для каждого модель выбирает `template_id` или `none`, направление и релевантность от 0 до 3. Ответ — строгий JSON. |
| 4. Подтверждение | код | Событие проходит в трёх случаях: (а) у кластера есть **≥ 2 независимых владельца** — перепечатка AP на 30 местных сайтах считается одним AP; (б) есть 1 новость, и числовой ряд сдвинулся в ту же сторону; (в) источник официальный. Иначе событие становится «слухом»: карточка без эффекта или отказ. |
| 5. Шаблон | модель | Один вызов на ≤ 15 прошедших кандидатов: шаблон, товар, регион, сила S/M/L, длительность, заголовок без цифр с плейсхолдерами `{pct}` и `{region}`, `source_ids`, дословная цитата-доказательство. |
| 6. Проверка | код | `source_ids` есть среди входных; цитата буквально найдена в заголовке источника; шаблон разрешён для этого товара; в тексте модели нет цифр. Сила считается по формуле (§3). Опционально второй, независимый вызов модели-критика: «подтверждает ли источник событие? да/нет». |
| 7. Публикация | код | Файл `world/2026-11-14.json`. В нём 8–15 активных событий, индексы цен по 10 товарам (база 100) и все ссылки. В продакшене основатель тратит 2–5 минут в день на страницу «approve / reject». |

**Два слоя реальности в матче:**
- **Фон.** Индексы цен из данных молча задают стартовые закупочные цены матча (`cost = base × index/100`). Игрок видит их в ленте «Market today».
- **Передний план.** 3–4 карточки событий во время матча.

Индекс возвращается к 100 на 10% в сутки, если новых данных нет. Так мир не уплывает от базы.

**Совпадение по времени.** Раунд = месяц, поэтому месячные ряды (Pink Sheet, FAO) переносятся 1:1: реальные «+6% за месяц» дают «+6% за раунд».

## 2. Защита от выдумок

1. **Закрытые списки вместо свободы.** `template_id`, товар, регион, сила (S/M/L), длительность (1/2/3/4/6) и предупреждение (0/1/2) — всё в JSON-схеме задано через `enum`. Structured outputs не поддерживает `minimum`/`maximum`, поэтому числа тоже задаём перечислением, а SDK дополнительно проверяет схему на клиенте.
2. **Модель не пишет чисел.** Цифры в карточку подставляет код из данных или из таблицы силы. Если в заголовке модели есть цифра, он отклоняется.
3. **Ссылку даёт база, а не модель.** Модель возвращает только `source_ids` из выданного ей списка, а URL, издание и дату код берёт из базы.
4. **Цитата-доказательство.** `evidence_quote` проверяется точным совпадением подстроки. API Citations с structured outputs несовместим (возвращает 400), поэтому проверка своя.
5. **Правило двух источников** или «новость + данные» (шаг 4).
6. **Прозрачное усиление.** Карточка показывает и реальное число, и игровое: «Real: +6.1% · In match: +9%». Множитель k ≤ 1,5, итоговый |m| ≤ 40%.
7. **Стоп-лист.** Новости о войнах, терактах, жертвах катастроф и частных лицах не становятся событиями. Если такая новость сдвинула цену, в игру попадает только экономический факт из данных («Wheat export disruptions»), без людей и без шуток, и всегда после ручной проверки.
8. **Авторское право.** Игроку показываем свой пересказ (до 90 символов), название издания, дату и ссылку. Текст статей не воспроизводим. Детали лицензий — в отчёте 22.

## 3. Каталог из 15 шаблонов

Обозначения: m — знаковая сила эффекта; T — длительность в раундах; e(t) — огибающая: полная сила первые ⌈T/2⌉ раундов, затем линейно до 0. Если шаблон опирается на данные, m = clamp(k·Δ, ±cap), где Δ — реальное относительное изменение ряда. Если только на новости, m = ±{S: 0,08; M: 0,15; L: 0,25} — это дизайн-константы, их надо проверить в симуляторе 24.

| # | Шаблон | Триггер → источник | Эффект в матче (считает код) | Границы, T, предупреждение | Контрход игрока |
|---|---|---|---|---|---|
| 1 | COMMODITY_PRICE | месячное изменение цены: Pink Sheet (кофе, какао, сахар, пшеница → мука), FAO (молочка) | `cost[g] ×= 1 + m·e(t)` | k = 1,5, cap 0,4; T 3–6; за 1 раунд | запас, фиксированный контракт |
| 2 | SUPPLY_SHORTAGE | дефицит у поставщиков, 2 источника (так же цветы: открытых цен на них нет) | `stock_cap[g] ×= 1 − |m|·e(t)`; остаток идёт с торгов между игроками | 0,2 / 0,35 / 0,5; T 2–4; за 1 | скупить поставщика, перейти на замену |
| 3 | HARVEST_WARNING | засуха или заморозки в регионе-производителе: новость + Open-Meteo / FAO | через 2 раунда запускает шаблон 1 | M/L; задержка 2 | закупиться до удара |
| 4 | ENERGY_PRICE | электричество и газ (EIA; по ЕС проверить источник) | `fixed_cost += E0·m·e(t)` | k = 1, cap 0,3; T 3 | вложиться в оборудование |
| 5 | FUEL_DELIVERY | бензин и дизель (EIA, еженедельно) | стоимость доставки заказа `×(1+m)` | k = 1, cap 0,3; T 2–3 | убрать доставку, поднять цену |
| 6 | SHIPPING_DISRUPTION | забастовка в порту, закрытие пролива, 2 источника | `lead_time[импорт] += 1`, `cost[импорт] ×= 1+m` | S/M; T 2–4; без предупреждения, не больше 1 за матч | местный поставщик дороже |
| 7 | LOCAL_WEATHER | реальный прогноз для города матча (Open-Meteo) | жара: холодное +20%, горячее −10%; дождь: поток −15% | таблица; T 1; видно всем заранее | ассортимент, персонал |
| 8 | FX_MOVE | курс местной валюты к USD за 30 дней (ЕЦБ) | `cost[импорт] ×= fx_t / fx_0` | k = 1, cap 0,25; до конца матча | местные поставщики |
| 9 | RATE_DECISION | решение ЦБ (сайты Fed и ECB) | ставка плавающих и новых кредитов `+= 4·Δ` | cap ±2 п.п.; за 1 раунд | фиксированная ставка, погасить долг |
| 10 | CONSUMER_MOOD | инфляция, потребительские настроения (официальная статистика) | `D_total ×= 1+m`; при m < 0 эластичность `ε ×= 1 + 0,5|m|` | S/M; T 3–4 | дешёвая линейка, лояльность |
| 11 | TREND_SPIKE | вирусный тренд продукта, 2 источника | `appeal[product] += m` — смещает доли спроса | M/L; T 2–3; за 1 | первым вывести продукт |
| 12 | TAX_CHANGE | закон о налоге или сборе (гос. сайт) | `tax += Δ` или `cost[g] += c` за единицу | реальное Δ; за 1–2 (у законов есть дата вступления) | цена, ассортимент |
| 13 | WAGE_RULE | МРОТ, дефицит кадров, забастовка | `wage ×= 1+m`; переманивание дороже на m; пул найма −k | S/M; до конца матча | автоматизация, удержание |
| 14 | RENT_INDEX | индекс коммерческой аренды или новость | резервная цена на торгах аренды `×(1+m)` | S/M; со следующих торгов | длинный договор заранее |
| 15 | CITY_EVENT | праздник или фестиваль в городе матча (Nager.Date) | `D ×= 1+m` в раунд события | 0,1–0,3; видно заранее | запас, персонал, реклама |

Шаблоны 7, 8, 15 и фон работают **без модели**, только код и API. Модель нужна там, где триггер — текст новости (2, 3, 6, 11–14), а в 1, 4, 5, 9, 10 она лишь пишет заголовок.

## 4. Как событие попадает в матч

- **Сколько:** 3–4 карточки на 12 раундов, примерно в раундах 1, 4–5, 8 и 10. Плюс погода и праздник города как фон. Не больше одного крупного негативного события на 3 раунда (правило из отчёта 05).
- **Одинаковы для всех игроков в матче — да.** Глубина PvP рождается из разной подверженности: кто сделал запас, кто скупил поставщика, кто сидит на импортном зерне. Одна новость бьёт по игрокам по-разному, и в этом вся стратегия.
- **Выбор событий:** код берёт события из файла дня, взвешивает их по пересечению с бизнесами на улице, силе и свежести (новость до 7 дней — вес ×2). Случайность задаётся `match_id`, поэтому матч воспроизводим. Правило баланса: каждый тип бизнеса на улице получает хотя бы одно событие по своему сырью, чтобы никого не выбивали прицельно.
- **Предупреждать — да, 3 из 4 событий за 1 раунд:** «Forecast: arabica costs expected to rise next round». В реальности прогнозы погоды, урожая и даты вступления законов тоже известны заранее. Предупреждение рождает атаки: скупить запас поставщика раньше соперников. Одно внезапное событие (шаблон 6) — максимум средней силы.
- **Разведка за игровые деньги:** найм «Market Analyst» за $X за раунд показывает следующее событие на раунд раньше остальных. Реальными деньгами преимущество не продаётся.
- **Карточка** (числа ниже — пример, не реальные данные):

```
☕ Arabica costs climb after dry spell in Brazil
Real world: Arabica +6.1% m/m — World Bank Pink Sheet, Oct 2026
In this match: bean cost +9% for 4 rounds, from round 5
Sources: World Bank · Reuters (12 Nov) ↗
```

## 5. Стоимость в токенах в сутки

**Один общий файл мира в день** (все цифры — оценка):

| Вызов | Вход / выход (вместе с thinking) | Opus 5.5, effort low | Haiku 5.5 |
|---|---|---|---|
| 3. Значимость, ~60 кластеров | ~8k / ~3k | $0.09 | $0.002 |
| 5. Шаблон, ≤ 15 кандидатов | ~15k / ~5k | $0.16 | — |
| 6. Критик (опционально) | ~10k / ~1,5k | $0.07 | $0.002 |
| **Итого за сутки** | | **≈ $0.32 (~$10 в месяц)** | Opus на шаге 5 + Haiku на 3 и 6 ≈ $0.17 |

Batch API (ночная задача, задержка не важна) режет сумму ещё на 50%: ~$5 в месяц. Кэш промпта при 2–3 вызовах в сутки почти ничего не даёт.

**Если читать новости на каждый матч:** ~30k токенов статей на матч, это ≈ $0.14 на Opus 5.5. При 1 000 матчей в день получается ≈ $140 в день, ~$4 200 в месяц. Общий файл в **~400 раз дешевле**. Кроме того, все матчи дня играют в одном мире: их можно сравнивать, считать рейтинг и разбирать.

**Внутри матча вызовов модели ноль.** События выбирает код. Опциональная «газета раунда» из отчёта 06 на Haiku стоит ~$0.0005 за матч.

**Вывод:** при общем файле стоимость модели перестаёт влиять на юнит-экономику (~$10 в месяц против цели $8 300 выручки в месяц). Поэтому можно брать сильную модель там, где важна точность. Выбор модели для продакшена — за вами.

## 6. MVP за 4 часа

| Время | Что делаем |
|---|---|
| 0:00–0:45 | `templates.ts`: 15 шаблонов как конфиг, чистая функция `applyEvents(state, events, round)` и тесты Vitest (каждый шаблон двигает свою переменную и не выходит за границы). |
| 0:45–1:45 | `scripts/build-world.ts`, запускается вручную: GDELT DOC API по 10 товарам, курсы ЕЦБ (XML), Open-Meteo для 3 демо-городов. Цифры Pink Sheet — 6 штук руками из последнего PDF в `data/commodities.json`: парсить Excel за 4 часа не успеем. |
| 1:45–2:45 | Один вызов модели через уже запланированный прокси `/api/ai`, structured outputs (Zod: `client.messages.parse` + `zodOutputFormat`), валидаторы из §2. На выходе — `world/<дата>.json`. |
| 2:45–3:30 | UI: карточка события, кнопка «Sources» со ссылкой, лента «Forecast», расписание из 3 событий на раунды 1/5/9 с предупреждением. |
| 3:30–4:00 | `?demo=1` загружает зафиксированный `world-demo.json`. Если API упал, срабатывает фолбэк. |

**Заготовить вручную для демо:**
1. `world-demo.json`: 5–6 событий из реальных новостей последних 30 дней (взять из отчёта 22), у каждого по 2 ссылки, проверенные человеком, и реальное число из данных.
2. Одно драматичное событие в раунде 6, например кофейный шок с предупреждением в раунде 5. На нём видно, как жюри-игрок, сделавший запас, обгоняет соседа.
3. Реальная погода демо-города на сегодня (Open-Meteo, с кэшем на случай сбоя).
4. Слайд или живой счётчик конвейера: «612 headlines → 48 clusters → 9 confirmed → 4 events». Это ответ на вопрос «а ИИ не выдумывает?».
5. Кнопка «Refresh world» запускает конвейер вживую с таймаутом 20 секунд. Это бонус: показ не зависит от неё.

## Что проверить

- Условия GDELT (бесплатно, в том числе коммерческое использование со ссылкой на GDELT) я видел только в пересказах, официальную страницу не открывал. Ограничение частоты запросов к DOC API не подтвердил.
- Бесплатный ключ Guardian — только для некоммерческих проектов; лимит, по разным источникам, 5 000 или 500 запросов в сутки. Для продакшена нужен коммерческий ключ.
- Лицензию Pink Sheet (CC BY 4.0) я видел только в каталоге-посреднике. Коммерческие условия Open-Meteo не проверял. Это зона отчёта 22.
