# Агент 05 — ИИ-сервис: погода, события, советник, подбор ниши, разбор

Пакет `@ohh/ai` (папка `ai/`) реализует раздел 8 `build/CONTRACT.md`. Всё работает без ключа API и без сети. Ключ включает тексты от модели, но деньги по-прежнему считает код.

|---|---|---|---|

Источники норм:
- температуры — таблицы NWS [максимумов](https://www.weather.gov/media/okx/Climate/CentralPark/DailyMaxTNormals.pdf) и [минимумов](https://www.weather.gov/media/okx/Climate/CentralPark/DailyMinTNormals.pdf);
- дни с осадками за январь, март, август, сентябрь и декабрь — [ежемесячные климатические отчёты NWS (CLM)](https://forecast.weather.gov/product.php?site=NWS&product=CLM&issuedby=NYC); остальные месяцы помечены `estimate`;
- снежные дни — [таблица в Wikipedia со ссылкой на NOAA](https://en.wikipedia.org/wiki/Climate_of_New_York_City);
- дни от 90 °F — [таблица NWS](https://www.weather.gov/media/okx/Climate/CentralPark/90DegreeDays.pdf), это средние с 1869 года.

**Как получается ряд.**
- Для каждого месяца из норм и сида считается план: сколько дней дождя, снега, шторма и жары. Используется вероятностное округление, так что в среднем по сезонам число совпадает с нормой.
- Жара идёт одной волной, остальные дни перемешаны.
- Температура = норма дня (интерполяция между серединами месяцев) + отклонение AR(1), чтобы тёплые и холодные дни шли сериями.
- День зависит только от `(seed, day)`, поэтому любое окно прогноза согласовано с любым другим.

**Как `deckEvent` выбирает событие.** Функция детерминирована.
- Объявление только по игровым понедельникам и не больше одного события в неделю; события ИИ тоже считаются.
- Приоритет:
  1. события с реальной датой, за 1–2 недели;
  2. погодное предупреждение, если такая погода есть в прогнозе на окно события;
  3. случайная карточка по весам — в 35% недель её нет.
- У каждой карточки свой интервал повтора.
- Событие не накладывается на событие той же темы; плавающие карточки не накладываются и на события того же вида.
- Уличные события берут улицу из `ctx.places`; эффекты по нишам режутся до ниш, которые есть в городе.
- За сезон выходит 39–44 события.

**Белый и чёрный списки** — в `src/events/themes.ts`.
- 29 тем. У каждой: вид, разрешённые месяцы, цели эффектов с узкими диапазонами внутри 0,7–1,3, масштаб (город или улица), максимальная длина, иногда нужная погода.
- Запрещённые слова: гибель, ранения, катастрофы, ураганы, наводнения, пожары, война, преступления, протесты, выборы, эпидемии.
- Сезонные слова (снег, метель, жара, праздничные рынки) разрешены только в своих месяцах.

## 4. `planEvents`: как ИИ планирует, а код проверяет

Модели даются:
- дата, прогноз на неделю, последние события, ниши и улицы города;
- темы с месяцами и диапазонами эффектов.

Модель отвечает JSON по схеме:
```
{ events: [{ themeId, kind, title, text, startInDays, durationDays, block, effects: [{ target, mult, niches, tiers }] }] }
```

Событие отбрасывается, если:
- тема не из списка или вид не совпадает с темой;
- до начала меньше `EVENT_NOTICE_DAYS` или больше 28 дней;
- длина больше допустимой для темы;
- хотя бы один день события вне месяцев темы или в тексте сезонные слова не по сезону (метель в июле);
- прогноз на эти дни противоречит теме;
- цель эффекта не из темы, множитель вне 0,7–1,3 или вне диапазона темы (множитель 3);
- ниши или улицы нет во входе;
- в тексте запрещённая тема, суммы или проценты (их считает код), текст не на простом английском или неверное число предложений;
- та же тема уже идёт или объявлена на этой неделе.

Если валидных событий не осталось, функция возвращает пустой список, и хост берёт колоду. Причины отказа пишутся в журнал вызовов.

## 5. Провайдер

- **SDK.** Claude через официальный `@anthropic-ai/sdk` 1.8.0. Модель — `AI_MODEL`, по умолчанию `claude-opus-5-5`. Структурированный ответ — `output_config.format: zodOutputFormat(schema)`, глубина — `output_config.effort: "low"`. `temperature`, принудительного `tool_choice` и выключения `thinking` нет — так велит документация skill `claude-api`.
- **`create` вместо `parse`.** Задание называет `client.messages.parse`, но тест против локального фейка API показал: `parse` разбирает JSON внутри SDK и при отказе модели бросает `AnthropicError` раньше, чем можно прочесть `stop_reason`. Поэтому вызов — `client.messages.create` с тем же форматом, как документация описывает `create`:
  1. сначала проверяется `stop_reason`: `refusal`, `max_tokens`, `model_context_window_exceeded`;
  2. потом текст разбирается методом `format.parse` того же хелпера.
- **Бюджет 8 секунд.** Свой таймер на `AbortController` (`AI_TIMEOUT_MS`, не больше 8000) и `maxRetries: 0`: повтор запроса сломал бы бюджет, а запасной путь есть всегда.
- **Кэш** — по хэшу (провайдер, модель, задача, system, prompt), до 300 ответов. Ответ, который не прошёл проверку, не кэшируется.
- **Лимит** — `AI_MAX_RPM` запросов в минуту (по умолчанию 20), сверх лимита сразу запасной путь.
- **Журнал** — последние 200 вызовов в памяти (`aiLog()`), при `AI_LOG=1` ещё и в stderr. Пишутся задача, провайдер, модель, исход, время, хэш входа и длина промпта; ключей и текста промпта в журнале нет.
- **Отключение ИИ.** `AI_PROVIDER=mock` или отсутствие `ANTHROPIC_API_KEY` — запасной путь без сети. SDK загружается лениво и только на сервере. Браузер импортирует `@ohh/ai/pure`.
- **Server-side fallbacks** (бета) не включены. Бета-вариант `messages` с форматом в документации skill не описан, а отказ и так уводит на детерминированный путь.

**Стоимость (оценка).** Цены Opus 5.5 — $4 за миллион входных и $20 за миллион выходных токенов (таблица моделей в skill `claude-api`).
- Промпт `planEvents` — около 2,1 тыс. токенов на входе (замер: 7,3 тыс. символов), выход — 300–600 токенов (оценка). Это около $0,02 за вызов, около $1 за сезон одного мира при вызове раз в неделю.
- Вопрос советнику — около $0,01.

## 6. Советник

- **Намерение вопроса** определяется по словам: срезать угол, найм, поставщик, разрешение, налог, цена, аренда, деньги.
- **Карточки** берутся из пакета ниши и `_common`: правила, нарушения, способы срезать угол, шаги плана, поставщики, роли, налоги, разрешения. Отбор — по совпадению слов с расширением («barista» → staff, wage).
- **Шаблон считает числа сам:**
  - стоимость работника = ставка × часы в месяц;
  - потерянные продажи против мощности работника;
  - экономия срезанного угла по `saves.basis`;
  - штраф через 6 месяцев по формуле CONTRACT §5: `base + perMonth × месяцы + pctOfSaved × сэкономлено`, с потолком `max`.
- **О нарушениях — честно:** сколько экономит, какой закон, какой штраф через полгода и что это бывает уголовным делом.
- **Ответ модели принимается**, только если:
  - в нём не больше 90 слов и есть хотя бы одно число;
  - каждое число есть в данных (допуск 3%);
  - нет поощрения нарушений («nobody will notice»).
  - Источники — только из карточек, которые были в запросе.

## 7. Подбор ниши и разбор

**Подбор ниши** (`interpretIdea`).
- Ключевые слова по пяти нишам, «сильные» слова считаются вдвое; «bed and breakfast» не считается завтраком.
- Ниша без пакета заменяется ближайшей играбельной с пояснением: B&B → кафе, deli → кафе.
- Ярус места: «premium/busy/subway» против «small/cheap/quiet». Набор: lean / standard / premium.
- Заметки содержат числа только из пакета (стоимость набора и стартовый капитал). Про веганское меню процент не пишу: источника нет.
- Ответ модели проверяется: ниша играбельная, набор существует, имя и заметки на простом английском.

Пример (запасной путь): «a small vegan coffee place near a subway» → cafe, «Leaf Cafe», mid, lean, три заметки.

**Разбор** (`writeDebrief`).
- Три главные потери — `RealWorldPlan.lessons` без изменений.
- Модель пишет только заголовок, «что получилось» и «что сделать в следующий раз». Её текст отбрасывается, если в нём есть число не из данных.

## 9. Ограничения и риски

1. Без пакетов `packs/*.json` (агенты 14–16) советник работает на фикстурах из `src/__stubs__/fixtures.ts`. Числа там из примера `build/PACK.md`, а не данные. Как только пакеты появятся, демо подхватит их само; советнику пакет приходит во входе.
2. Семь месяцев дождливых дней — оценка. Нужен один прогон `fetch-climate.mjs` там, где открыт `www.ncei.noaa.gov`. Коды рядов NCEI (`MLY-PRCP-AVGNDS-GE001HI` и другие) взяты из документации норм по памяти и требуют проверки при первом запуске.
3. Три карточки правил информационные: в `EffectTarget` нет целей «зарплата» и «частота проверок».
4. Путь с настоящей моделью не прогнан: ключа у агента нет. Форма запроса проверена тестом против локального фейка API.
