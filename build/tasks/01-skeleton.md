# Агент 01 — Каркас, склейка и деплой

> Зачем: Ты делаешь каркас проекта и отвечаешь за то, чтобы все куски собрались в одно приложение.
> Твои папки: корень репозитория (`package.json`, `tsconfig.base.json`, `README.md`, `scripts/`, `Dockerfile`), `shared/` (кроме `src/types.ts` и `src/rules.ts`), `engine/src/niches/index.ts`

Прочитай по порядку: `context/08-game-v5.md` (что за игра), `context/06-team.md` (журнал и ветки), `build/PROTOCOL.md`, `build/CONTRACT.md`, `shared/src/types.ts`, `shared/src/rules.ts`. Затем выполни задание. Людей не спрашивай — решай сам и записывай решения в журнал `agents/01.md`. Никого не жди: чужого куска нет — работай на заглушке и своих примерах данных.

## Шаг 1 — каркас (первые 20 минут, затем сразу пуш)

- npm workspaces: `shared`, `engine`, `ai`, `host`, `server`, `bots`, `client`. В каждом — `package.json` с именем `@ohh/…`, `tsconfig.json`, `src/index.ts` с экспортами-заглушками строго по сигнатурам `build/CONTRACT.md`, один проходящий тест. Чужие папки создаёшь только как пустой каркас; содержимое пишут их владельцы.
- Корневые скрипты: `npm run dev` (сервер и клиент вместе), `npm test`, `npm run check` (tsc --noEmit по всем пакетам), `npm run build`, `npm start` (сервер раздаёт собранный клиент на одном порту).
- `shared/src/index.ts` реэкспортирует `types.ts` и `rules.ts`. `shared/src/util/`: `clamp`, `round2`, `sum`, `formatMoney`, сидируемый генератор `mulberry32`, `uid(seed, n)`.
- `client`: Vite + React + TypeScript, страница «OK». `server`: Express, `GET /api/health`.
- `README.md`: запуск за три команды.
- В журнале: «каркас запушен, ветка такая-то» — ведущий перенесёт его в основную ветку.

## Шаг 2 — сквозная проверка (`scripts/smoke.mjs`)

Это проверка из раздела 10 файла `context/08-game-v5.md`, по HTTP: поднять сервер → создать демо-город → два владельца входят и открывают кафе по рекомендованному набору → город проходит 35 игровых дней → у обоих есть `MonthReport` → первый жалуется на второго → дело, проверка, уведомление → кросс-промо между ними принято → у обоих в `view` есть аналитика. Пока чужих кусков нет — на заглушках; по мере вливания заглушки исчезают. Скрипт печатает, какой шаг прошёл на настоящем коде, а какой на заглушке. Он должен быть зелёным всегда.

## Шаг 3 — склейка (до конца хакатона)

- Каждые 30 минут: `git fetch`, ветки `claude/*`, журналы `agents/*.md`. Готовые куски вливай в свою ветку, чини конфликты и типы, гоняй `npm run check`, `npm test`, `node scripts/smoke.mjs`, пушь. Ведущий забирает твою ветку в основную.
- `engine/src/niches/index.ts`: реестр `Partial<Record<NicheId, NicheHooks>>`; добавляй импорт, когда вливаешь ветку ниши.
- `scripts/validate-all.mjs`: прогоняет `build/validate-pack.mjs` по всем `packs/*.json`.
- В журнале — таблица: агент, ветка, что влито, что сломано, что ещё на заглушке. Чужой код не переписывай: поломку описывай в разделе «Для агента NN» — владелец увидит его при слиянии основной ветки.
- Порядок склейки: сначала 02 + 06 + 08 (город идёт, клиент показывает бизнес), затем 03, 13, 04, 10, потом остальное.

## Шаг 4 — деплой

Один сервис Node, один порт, снимки мира на диске. `Dockerfile` и инструкция для бесплатного хостинга с постоянным процессом (Render, Fly.io или Railway — выбери по документации и объясни выбор), плюс запуск с ноутбука в локальной сети. Сам ничего не разворачивай и аккаунтов не создавай: человек сделает это по `README.md`.

## Проверка

`npm install && npm run check && npm test && node scripts/smoke.mjs` — зелёное на чистом клоне.
