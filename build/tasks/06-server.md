# Агент 06 — Сервер: сезоны, сокеты, таймер

> Зачем: Ты связываешь игроков: комната-сезон, вход, раунды по таймеру, рассылка каждому его картины мира.
> Твои папки: `server/`

Прочитай по порядку: `context/FULL.md`, `context/06-team.md`, `build/PROTOCOL.md`, `build/CONTRACT.md`, `shared/src/types.ts`. Затем выполни задание. Людей не спрашивай — решай сам и записывай решения в журнал `agents/06.md`.

## Что сделать

Сервис из `build/CONTRACT.md`, раздел 6. Типы событий — `ClientToServer`, `ServerToClient`, `ClientView` в `shared/src/types.ts`.

1. **Сезон.** `POST /api/season` создаёт сезон из `SeasonConfig` (в демо: 10 мест владельцев, 3 госслужащих, 12 раундов по 40 секунд, таблица призов 50/30/20). Код сезона — 4 буквы; `season:join` без кода ведёт в открытый сезон или создаёт новый.
2. **Вход.** `season:join` выдаёт `playerId` и `token`; повторный вход с `token` возвращает игрока на место после обрыва связи или перезагрузки страницы. `season:pay` — тестовый взнос: `bank += entryFee`. Госслужащие входят бесплатно и выбирают роль.
3. **Фазы** `lobby → setup → decide ⇄ resolve → ended` с серверным таймером; `tick` раз в секунду. `season:start` заполняет пустые места ботами (`@ohh/bots`: `fillSeats`, `botDecisions`, `botOfficialDecisions`; пока их нет — заглушка: бот повторяет рекомендованные решения) и запускает `setup`.
4. **Раунд.** Собирает `turn:submit` и `official:submit`; раунд закрывается, когда ответили все люди или вышло время; за молчащих ходит автопилот. Затем `resolveMonth` из `@ohh/engine`, после 12-го месяца — `finalizeSeason` и `debrief` каждому владельцу.
5. **Картина мира.** Функция `buildView(state, playerId): ClientView` — единственное место, где решается, кто что видит: владелец — свой бизнес полностью, чужие — только `PublicBusiness`; чиновник — `OfficialCase` без чужих касс; зритель — открытое. Аналитика и советы — из `@ohh/engine` (`analyze`, `recommend`). Рассылка `view` после каждого изменения.
6. **Запросы с ответом:** `business:recommend` → `recommendOpening`; `business:open` → `openBusiness`; `turn:whatif` → `whatIf`; `advisor:ask` → `askAdvisor` из `@ohh/ai`.
7. **ИИ-события.** Во время `decide` месяца N сервер зовёт `getWeather` и `planEvents` для месяца N+1 и кладёт результат в `state.events`; ответ не пришёл к концу раунда — берётся запасной из колоды. Расчёт месяца ИИ не ждёт никогда.
8. **Данные.** При старте читает `packs/*.json` и `data/places.json`; нет файла — примеры из `server/fixtures/`. `GET /api/packs`, `GET /api/places`.
9. **Надёжность.** Проверка каждого входящего сообщения (форма, фаза, чей ход, лимиты); ошибка в одном сезоне не роняет процесс; снимок состояния в `server/.snapshots/<id>.json` после каждого месяца и восстановление при перезапуске; `GET /api/season/:id` для проектора.
10. **Демо-режим.** `POST /api/season` с `demo: true` и параметром `speed` — раунд 15, 40 или 90 секунд; `POST /api/season/:id/skip` закрывает раунд досрочно (для показа жюри).

Пока движка нет в основной ветке — заглушки по сигнатурам в `server/src/__stubs__/`; все обращения к чужим пакетам идут через один файл `server/src/deps.ts`, чтобы замена была в одном месте.

## Тесты

Интеграционный на `socket.io-client`: три клиента проходят сезон из трёх месяцев; обрыв и возврат по `token`; опоздавший ход отклоняется; владелец не получает чужую кассу ни в одном `view`.

## Проверка

`npm test -w @ohh/server` зелёный; `npm run dev -w @ohh/server` и `npx tsx server/scripts/play.ts` проигрывает сезон тремя скриптовыми клиентами и печатает итоговую таблицу.
