## Правила

1. **Веб-поиск на всём протяжении работы.** Первоисточники: nyc.gov, ny.gov, irs.gov, bls.gov, тексты законов, прайсы поставщиков, отраслевые отчёты. Для неочевидного — рассказы владельцев: Reddit, форумы, блоги, новости о закрытиях. Английский обязателен; русский и ещё один язык — для неочевидного и для сравнения.
2. **Каждое число имеет `source` и `confidence`.** `verified` — сам открыл первоисточник и увидел число. `estimate` — оценка, расчёт в `note`. Выдуманных чисел и ссылок нет. Не нашёл — пиши в раздел «Не найдено» отчёта.
3. **Нью-Йорк, 2026 год, маленькое заведение одного владельца.** Месяц — единица времени.
4. **Случая нет.** В расчёте месяца нет вероятностей. Событие либо объявлено заранее и действует на всех, либо следует из решения игрока: сэкономил на обслуживании — поломка через N месяцев. Частоту из жизни записывай справочно.
5. **Каждая находка становится записью пакета.** Разделы: `setup`, `monthlyCosts`, `staff`, `taxes`, `levers`, `shortcuts`, `violations`, `officials`, `reports`, `events`, `ruleCards`, `roadmap`, `suppliers`, `benchmarks`. То, чего формат не выражает, идёт в `extra` (описано ниже) и в «Просьбы к ведущему».
6. **У каждого события есть ход игрока.** Законное решение (`levers`) или срезанный угол (`shortcuts` и его `violations`). Событие без выбора — это кубик, а не игра.
7. **Язык.** Строки для игрока — на английском, отчёт — на русском. Идентификаторы — `snake_case`, не повторяют существующие. Исправление существующей записи делается тем же `id` и строкой в отчёте «исправляю, потому что…».
8. **Уровень у каждой записи в `extra`.** `core` — без этого неправдоподобно; `deep` — добавляет глубину; `exotic` — редкое.
9. **Запрещено:** войны и катастрофы с гибелью людей; настоящие заведения как цели; вероятности в расчёте; править код движка и общие файлы. Ты сдаёшь данные и описание механик.
10. **Минимумы в заданиях — порог сдачи, а не цель.** Не останавливайся на них.

### Расширенные записи в `extra`

`extra.eventCatalog` — события, которым мало раздела `events`:

```json
{
  "id": "icy_sidewalk",
  "name": "…",
  "text": "…",
  "scale": "point",
  "months": [12, 1, 2],
  "realSignal": "настоящий показатель, который запускает событие",
  "effects": [{ "field": "…", "mult": 0.9 }],
  "durationMonths": 1,
  "playerMoves": [{ "kind": "lever", "id": "…" }, { "kind": "shortcut", "id": "…" }],
  "realFrequency": "справочно, с источником",
  "tier": "core",
  "source": "https://…",
  "confidence": "estimate",
  "note": "расчёт"
}
```

Значения в примере — заглушки, не данные. `scale`: `point`, `block`, `city`, `country`, `world`.

`extra.mechanics` — механика, которой нет в формате:

```json
{
  "id": "buy_existing_business",
  "title": "…",
  "playerDecision": "что решает игрок",
  "engineMath": "что и как считает движок",
  "fieldsNeeded": ["какие поля добавить в пакет"],
  "numbers": [{ "what": "…", "value": 0, "source": "https://…", "confidence": "estimate" }],
  "tier": "core"
}
```

## Задания

Затравки даны для кафе в Нью-Йорке. Это вещи, которые нужно найти и проверить, а не готовые факты. Для другой ниши сохрани тему задания и подбери свои затравки.

### D00 — Тотальный поиск (для Codex)

**Тема.** Пройти весь интернет по нише и собрать всё, что может случиться с таким бизнесом, без деления на темы.

**Обязательно:**

1. Каталог событий и случаев по всем масштабам: точка, квартал, город, страна, мир.
2. Истории закрытий: что именно убило заведение, с цитатой и ссылкой.
3. Неочевидное: чего новичок не предвидит, а владелец узнаёт на своей шкуре.
4. Проход по дню владельца по часам и по году по месяцам: что происходит и что идёт не так.
5. Сверка с `packs/<ниша>.json`: что из найденного там уже есть, чего нет.

**Минимум.** 300 записей в `extra.eventCatalog`; 150 пунктов в `extra.nonObvious` (`{ text, why, source }`); 60 историй в `extra.failureStories` (`{ what, cause, lesson, source }`); 200 источников.

### D01 — Вход в бизнес и месяцы до открытия

**Обязательно:**

1. Способы входа: с нуля; покупка готового бизнеса; франшиза; киоск, тележка, временная точка, уголок в чужом помещении. Для каждого: деньги, срок до первой выручки, риски.
2. Время от подписания аренды до открытия по шагам. Сколько месяцев аренда платится без выручки.
3. Договор аренды: депозит, личная гарантия, бесплатные месяцы на ремонт, индексация, платежи сверх аренды.
4. Ремонт: стоимость за квадратный фут, подрядчики, типичные задержки и перерасход.
5. Покупка готового бизнеса: из чего складывается цена, какие долги и нарушения переходят к покупателю, что не передаётся.

**Затравки для кафе:** задержки подключения газа и электричества; разрешения Департамента зданий; good guy guarantee; key money; уведомление налоговой штата при покупке бизнеса (bulk sale); передаётся ли разрешение на общепит новому владельцу; Commercial Rent Tax.

**Минимум.** 15 записей `setup`, 12 шагов `roadmap`, 25 событий в каталоге, 6 механик, среди них «ремонт без выручки» и «покупка готового бизнеса».

### D12 — Проверка чисел текущего пакета

**Тема.** В пакете много оценок вместо проверенных чисел. Их нужно проверить по первоисточникам.

**Обязательно:**

1. Выпиши из `packs/<ниша>.json` и `packs/_common.json` все числа с пометкой `estimate` и все числа без `source`.
2. Для каждого найди первоисточник. Нашёл — поставь `verified`, ссылку и, если нужно, исправь значение. Не нашёл — оставь `estimate` и уточни расчёт.
3. Открой заново не меньше 15 чисел, уже помеченных `verified`, и убедись, что источник говорит именно это.
